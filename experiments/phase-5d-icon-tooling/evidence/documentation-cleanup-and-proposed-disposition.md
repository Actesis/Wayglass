## Proposed disposition

**Proposed outcome:** accept a trimmed private build-and-validation artifact candidate.

The candidate capability consists of:

- one repository-owned structured source for the domain-neutral catalog;
- strict validation of identity, provenance, direction, accessible use, geometry, paint, and the
  narrow safe primitive subset;
- deterministic generation of runtime catalog data, source/output manifests, and a script-free
  review index; and
- byte-level drift and stable adverse-input diagnostics.

The proposal does not promote the experiment directory wholesale. The synthetic directional glyph,
runtime descriptor adapter, capacity corpus, warm/cold harness, manual dry-run machinery, security
audit harness, and cleanup tests are evidence or implementation references—not proposed production
exports. A permanent implementation contract must select the smallest surface and fix its budget
before implementation begins.

## Reasoning

The current inline path requires multiple synchronized edits and still lacks direction,
accessible-use metadata, deterministic preview generation, and targeted drift. The proof completes
that task from one source, rejects unsafe content, adds no dependency or runtime leakage, passes the
three current browser engines, and is fast at the fixed 500-record ceiling. Those repeated source,
validation, and review concerns belong to Wayglass because they govern its official generic catalog.

The contrary evidence remains material: the current production catalog contains only four glyphs,
the proof owns 1,551 nonblank source/test lines, domain neutrality still requires human review, and
the accepted foundation contract differs from the runtime implementation. The appropriate result is
therefore a trimmed private artifact candidate, not a public tool, package, runtime migration, or
claim that every application needs icons.
