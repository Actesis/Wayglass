# Phase 6B package identity and stewardship

**Status:** Accepted by the project owner on September 4, 2026. This record establishes complete
identity, legal, package-documentation, and maintenance baselines for the six-package v1 candidate.
Every package remains private at `0.0.0`; this acceptance does not make the repository public,
publish, reserve a registry package, choose compatibility ranges, create release automation, or
deploy documentation.

## Package identity

The package manifests now carry exact, consumer-readable metadata:

| Package              | Description                                                        | Documentation route   |
| -------------------- | ------------------------------------------------------------------ | --------------------- |
| `@wayglass/core`     | Framework-neutral state models for operational interfaces          | `/`                   |
| `@wayglass/tokens`   | Semantic design tokens and generated web artifacts for Wayglass    | `/foundations/tokens` |
| `@wayglass/themes`   | Wayglass themes and density modes for operational interfaces       | `/foundations/tokens` |
| `@wayglass/elements` | Domain-neutral Wayglass Custom Elements for operational interfaces | `/components/`        |
| `@wayglass/icons`    | Generated, direction-aware icons for Wayglass interfaces           | `/`                   |
| `@wayglass/react`    | Typed React bindings for Wayglass Custom Elements                  | `/frameworks/react`   |

Every package uses:

- `Apache-2.0` and `Wayglass contributors`, as accepted by ADR 0022;
- the canonical HTTPS documentation origin;
- the exact case-correct `Actesis/Wayglass` Git repository plus its package directory;
- the repository issue URL for future public defect reporting;
- four bounded search keywords led by `wayglass` and specific to the package;
- a future-public `publishConfig` pinned to `https://registry.npmjs.org/` with public scoped access;
  and
- `dist`, `README.md`, `LICENSE`, and `NOTICE` as the only proposed packed roots.

There is no funding mechanism, sponsor destination, or accepted funding promise, so manifests omit
`funding` deliberately. A later funding field requires a reviewed destination and stewardship owner.
`publishConfig` documents the intended registry and access but cannot override `private: true`;
publication remains impossible until the release approval changes privacy explicitly.

## Package documentation

Each package now has a package-specific README with:

- its purpose and non-goals;
- one minimal import or explicit-registration example;
- import-side-effect guidance appropriate to that package;
- a permanent contract-documentation link;
- links to shared support, security, and migration guidance; and
- Apache-2.0 attribution.

The READMEs describe private-candidate status rather than claiming that a version exists on npm.
Phase 6C must verify that the exact README, `LICENSE`, and `NOTICE` files survive packing.

## License, notice, source, and map policy

Every package directory contains byte-identical copies of the root Apache-2.0 `LICENSE` and
`NOTICE`. The package manifests include them explicitly, and any mismatch is a release blocker.

Authored TypeScript source is excluded from v1 tarballs. Built JavaScript, declarations, CSS, JSON,
JavaScript source maps, and declaration maps remain inside `dist` when generated by the accepted
build. Maps may contain only package-relative source names; they must not embed source content,
absolute paths, credentials, or personal paths. This preserves useful debugger and declaration
navigation while keeping one reviewed runtime/tool surface. Phase 6C must inspect every packed map
and prove the tarball contains neither authored source nor path leakage.

## Stewardship baseline

The repository now owns one shared maintenance system for all six packages:

- `CHANGELOG.md` records notable public changes by release unit without a changelog dependency;
- `MIGRATION.md` defines the required consumer migration shape and records no pre-release migration;
- `DEPRECATIONS.md` records no current deprecation and defines notice/replacement/removal fields;
- `SECURITY.md` withholds a public security-support promise before release and requires verified
  GitHub private vulnerability reporting before repository visibility or publication changes;
- `SUPPORT.md` separates released contracts from source, examples, and evidence and defines future
  issue-report content; and
- the release-note template requires identity, impact, compatibility, limitations, artifact
  evidence, publication, verification, and recovery details.

No response-time guarantee, funding promise, broad environment claim, public issue availability, or
security contact is invented. The later support-claim disposition remains authoritative for exact v1
environments, and enabling/verifying the named GitHub channels remains a release prerequisite.

## Validation and next gate

Validated locally on September 4, 2026:

- all 197 documentation/governance tests passed, including five new stewardship assertions and the
  updated completion guard;
- all six dry-run npm pack manifests, using an isolated temporary npm cache, included `README.md`,
  `LICENSE`, `NOTICE`, and `package.json` and contained no `src` entry;
- all 312 currently generated JavaScript and declaration maps used only relative source names and
  omitted `sourcesContent`;
- documentation TypeScript, focused ESLint, Prettier, include/link checks, and the VitePress
  production build passed; and
- `git diff --check` passed.

The dry runs validate the selected content policy but do not establish immutable tarball hashes or
replace Phase 6C clean-build and clean-consumer evidence. The repository's global npm cache has an
unrelated ownership problem, so validation used `/private/tmp/wayglass-npm-cache` without modifying
user-level state.

This acceptance closes Phase 6A corrections 4, 5, and 11 and advances Phase 6B to the version and
compatibility contract. It does not close packed-artifact evidence, choose versions or support
ranges, approve publication, or begin Phase 6C.
