# Wayglass Vision

> Technology should increase understanding, not complexity.

> **Naming status:** Wayglass is the confirmed project and product name. Use **Wayglass**
> consistently in documentation, examples, package names, and design discussions.

## 1. Why Wayglass Exists

Modern software can observe and control extraordinarily complex systems, yet many interfaces make those systems harder to understand.

Enterprise applications bury meaning in forms and navigation. Dashboards overwhelm users with charts. Control systems compete for attention with constant warnings. Minimal interfaces often remove so much context that users must hunt for basic state.

Wayglass exists to offer a different model.

A Wayglass interface should help a person answer three questions within seconds:

1. **Where am I?**
2. **What is happening?**
3. **What should I do next?**

The purpose of the interface is not to impress the user. Its purpose is to make the state of a system understandable and actionable.

## 2. Mission

Create an open, modern design language for high-awareness interfaces that turns complex systems into **known states**.

A known state is one in which the user can understand:

- the current condition of the system;
- what recently changed;
- what needs attention;
- which actions are available;
- what effect an action had;
- what remains uncertain or in progress.

No interaction should leave the user wondering whether something happened, whether the system is still working, or what to do next.

## 3. Vision

Wayglass will become a reusable design language and implementation ecosystem for software that monitors, coordinates, or controls complex systems.

It should be suitable for:

- smart homes and building automation;
- AI agent orchestration and supervision;
- operations and command centers;
- infrastructure and application monitoring;
- industrial and manufacturing controls;
- fleet, logistics, and field operations;
- security operations;
- healthcare and laboratory monitoring;
- administrative and enterprise applications;
- data-rich personal software;
- wall displays, kiosks, tablets, desktop applications, and phones.

Wayglass is not limited to dashboards. It supports the entire loop of **awareness, understanding, decision, action, and confirmation**.

## 4. The Name

A wayglass is imagined as an instrument through which direction becomes visible.

The name suggests:

- orientation;
- perspective;
- navigation;
- observation;
- instrumentation;
- exploration;
- an optimistic view toward what comes next.

The metaphor is an **instrument**, not a visual material. Wayglass does not imply glassmorphism, transparency-heavy interfaces, or ornamental visual effects.

## 5. Brand Position

Wayglass is:

> **A design language for operational awareness.**

It is inspired by optimistic visions of human-centered technology, but it is not a reproduction of any fictional interface and should not depend on franchise-specific terminology, assets, layouts, or branding.

The future Wayglass imagines is capable, humane, calm, and understandable.

## 6. Brand Promise

> **Wayglass turns complex systems into known states.**

Every Wayglass interface should improve situational awareness and reduce uncertainty.

## 7. Product Principles

### 7.1 Clarity over decoration

Every visible element must communicate structure, state, priority, relationship, or action.

### 7.2 Awareness over novelty

A design is successful because the user understands more, not because it looks unfamiliar or futuristic.

### 7.3 Confidence over surprise

The system should communicate what happened, what is happening, and what will happen next.

### 7.4 Calm over urgency

Attention is a limited resource. Routine information remains quiet so meaningful changes can stand out.

### 7.5 Consistency over cleverness

Predictable patterns create speed, trust, and muscle memory.

### 7.6 Accessibility over visual authenticity

No stylistic reference is more important than usability. Wayglass must work for people with different visual, motor, auditory, and cognitive needs.

### 7.7 Human language over system language

Users should see “Living room lights,” not internal entity identifiers, database keys, or implementation details.

## 8. Emotional Goal

A person using Wayglass should feel:

- oriented;
- informed;
- capable;
- calm;
- confident;
- in control.

The desired reaction is:

> “I understand what is happening.”

Not:

> “This looks futuristic.”

Beauty should emerge from coherence, precision, and clarity.

## 9. Visual Metaphor

Wayglass is an **instrument panel**, not merely a dashboard.

A dashboard reports.

An instrument panel supports awareness and action.

This distinction means Wayglass must show:

- current state;
- trends and recent changes;
- cause-and-effect relationships;
- available controls;
- action feedback;
- system confidence and uncertainty;
- priority without visual noise.

## 10. Audience

Wayglass serves three overlapping audiences.

### 10.1 End users

People who need to understand and operate a system without learning its implementation.

### 10.2 Product teams

Designers and engineers building complex, data-rich applications.

### 10.3 Contributors and AI coding agents

Humans and automated agents extending the system while preserving its philosophy, accessibility, architecture, and visual coherence.

## 11. What Wayglass Is Not

Wayglass is not:

- a Star Trek or LCARS implementation;
- a retro user-interface theme;
- a collection of decorative science-fiction components;
- a glassmorphism library;
- a dashboard template;
- a single application;
- an animation showcase;
- a replacement for sound information architecture;
- a reason to sacrifice accessibility;
- a visual skin placed over inconsistent interaction patterns.

## 12. Strategic Differentiation

General-purpose design systems primarily optimize for broad application development. Wayglass specializes in interfaces where users must quickly understand and act upon changing system state.

Wayglass differentiates itself through:

- explicit support for situational awareness;
- semantic treatment of state, confidence, urgency, and change;
- stable, instrument-like layouts;
- high information density without confusion;
- responsive behavior from phone to wall display;
- strong patterns for monitoring and control;
- framework-neutral foundations;
- design guidance that is executable by both humans and AI agents.

## 13. Measures of Success

Wayglass is successful when:

- users can identify important state within five seconds;
- users can distinguish routine, warning, and critical conditions without relying on color alone;
- actions provide immediate and unambiguous feedback;
- layouts remain stable during updates;
- responsive versions feel like the same product;
- components meet WCAG 2.2 AA requirements;
- teams can extend the system without inventing new visual rules;
- AI coding agents can implement components consistently from the repository documentation;
- applications built with Wayglass feel related without becoming visually identical.

## 14. The North Star

Every design and engineering decision should answer:

> **Does this increase situational awareness or reduce uncertainty?**

If the answer is no, the feature, visual element, or interaction probably does not belong.

## 15. Relationship to Other Documents

This repository begins with three governing documents:

1. **`VISION.md`** defines why Wayglass exists and what it intends to become.
2. **`DESIGN_PRINCIPLES.md`** defines how design decisions must be made.
3. **`SPEC.md`** defines how the design language and component ecosystem must be implemented.

When documents conflict, resolve the conflict in that order unless a legal, safety, security, or accessibility requirement demands otherwise.
